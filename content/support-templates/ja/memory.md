# メモリ — カスタマーサポート・テンプレート

## ドメインコンテキスト

サポートパーソンはキューの中で1日を過ごします。チケットはメール、チャット、ソーシャル、時には電話で来ます。プラットフォームは Zendesk、Intercom、Help Scout、Front、または個人創業者にとっては単純な Gmail。仕事は：チケットを読み、顧客が必要としているものを理解し、できることを決め、対応を書く。1日30〜100回繰り返す。

難しい対応はノーと言うもの — 拒否されたリファンド、「その機能を追加できません」、「あなたのアカウントは停止されました」。簡単なものは「今日発送、追跡リンクはここ」。ほとんどは中間に入ります。トーンは人々が考える以上に重要 — 冷たく vs. 暖かく届けられた同じ内容は、まったく異なる顧客反応を生み出します。

自身のサポートをしている個人創業者は、必要以上に通常暖かく、必要以上に遅い。スケールでのサポートチームはフォーマルをデフォルトとし、ロボットのように聞こえることになる。両方とも関係の価値をテーブルに残しています。

最良のサポートパーソンが理解している静かなルールもあります：あなたはチケットを解決しているだけでなく、会社の顧客の認識を構築（または侵食）しています。完璧に扱われた拒否されたリファンドは関係を救うことができる。不適切に扱われた認可されたリファンドはまだそれを失う可能性がある。

## AI が知っておくべき語彙

- **チケット**：顧客が開始したサポート会話。ステータス（オープン、保留、解決済み、クローズ）がある。
- **マクロ**：Zendesk の保存された対応テンプレート。Intercom は「保存された返信」と呼ぶ。Help Scout も「保存された返信」と呼ぶ。
- **初回応答時間（FRT）**：顧客が *何らかの* 返信を得るまでの時間。サポートで最も監視されるメトリック。
- **解決時間**：チケット作成から「解決済み」ステータスまで。FRT より正直でない — エージェントはそれを操作するために早期にクローズする。
- **CSAT**：顧客満足度。通常、チケットがクローズした後に送信される1〜5または1〜7の調査。「非常に満足」を90%超目指す。
- **NPS**：ネット・プロモーター・スコア。0〜10スケール。プロモーター（9〜10）、パッシブ（7〜8）、デトラクター（0〜6）。スコア = %プロモーター - %デトラクター。
- **デトラクター回復**：0〜6 NPS をくれた顧客への何が悪いかを見つけて修正しようとするアウトリーチ。
- **エスカレーション**：チケットをシニアレップ、マネージャー、または特殊チームに上げること。通常24〜48時間の内部 SLA がある。
- **SLA**：サービスレベル契約。約束された応答／解決時間、通常エンタープライズ契約。
- **リファンドウィンドウ**：購入後にリファンドが自動的に対象となる日数。業界規範：14日（SaaS）、30日（DTC）、365日（Costco）。
- **チャージバック**：顧客が販売者に尋ねる代わりに、銀行を通じて請求を争うこと。販売者にリファンドに加えて手数料（約 $15〜25）がかかる。
- **Stripe ダッシュボード**：ほとんどのモダン SaaS がリファンドを処理する場所。ワンクリック、5〜10日でお金が戻る。
- **サポートからのアップセル**：サポートインタラクション中にアップグレードされたプランを提供すること。顧客が満足しており、アップグレードが彼らの実際の問題を解決するときのみ適切。

## 一般的なワークフロー

- **リファンド依頼を処理する**：チケットを読む → 注文日とリファンドポリシーを確認 → 顧客履歴を確認（初回？長期？過去の問題？） → 決定：全額、部分、拒否 → 認可された場合、Stripe/Shopify で処理 → 解決と理由で返信 → 拒否された場合、2〜3の代替案を提供。
- **紛失注文を扱う**：注文が発送されたことを確認 → 追跡を確認 → 「配送済み」だが顧客がそう言わない場合、玄関ポーチの写真を依頼 → 本当に紛失した場合、交換または返金 → 頻繁に起こる場合は、バックチャネルで配送業者に連絡。
- **エスカレーションを承認する**：1時間以内に「これを [名前/チーム] にエスカレートしました」と現実的なタイムラインで返信 → 確認できない修正を決して約束しない → 次の更新時間の期待を設定。
- **NPS デトラクター回復**：0〜6スコアを見る → 24時間以内に本物の人から返信（「フィードバックありがとうございます！」ではない） → 1つの具体的な質問を尋ねる → 聞く → 適切であれば修正または補償を提案。
- **サポートからのアップセル（稀だが正しい）**：顧客が解決に満足 → 彼らの実際のニーズはより高いティアにある → 一度、簡潔に、計算とともに言及 → 押さない。

## 避けるべきこと／よくある間違い

- 「ご迷惑をおかけしたことに心よりお詫び申し上げます。」 底辺のサポートクリシェ。具体的な承認は常に一般的な謝罪を打ち負かす。
- 謝罪でリード、解決を埋める。顧客は何をしているか、次に理由を知りたい。
- 「弊社のポリシーにより...」理由を説明せずに。理由が意味をなす場合、理由を与える。意味をなさない場合、ポリシーを変える。
- 曖昧なタイムライン：「まもなく」、「すぐに」、「適切な時期に」。具体的であるか、沈黙する。
- 締めとして「ご質問があればお気軽にお問い合わせください」。実際の次のステップまたは本物のサインオフに置き換える。
- 実体の前の複数段落の謝罪。謝罪側で最大2文。
- フォームレター・サインオフ：「[会社] のチーム」、「Customer Happiness Team」。実際の名前を使用。
- 混合トーン — フォーマルで始まり、半分でウォームにスライドする。1つを選ぶ。
- 顧客が不満なときのアップセル。シニカルに読め、関係を殺す。
- 「このメールがお元気でいるところに届くことを願って。」 彼らは問題で書き込んだ。問題を認める。

## トーン／レジスター

優れたサポートライターは、自分のものを失うことなくブランドボイスに合わせます。彼らは顧客の読書レベルで書きます — 短い文、より少ないコンマ、平易な言葉。彼らは顧客が最初に使わなかったジャーゴンを決して使いません。彼らは甘ったるくない暖かさ、冷たくないプロフェッショナル、簡潔でない正直さ。彼らが私を意味するときに「私」と言い、会社を意味するときに「私たち」と言う。

内部語彙：チケット、マクロ、FRT、CSAT、エスカレーション、チャージバック、リファンドウィンドウ。外部語彙：「あなたの注文」、「あなたのアカウント」、「問題」、「何が起こったか」。顧客向けのコピーで内部ジャーゴンを決して使わない。

優れたサポートパーソンは、ブランドボイスが示唆する以上にわずかにダイレクトです。顧客は、長い丁寧な「お知らせするのは残念ですが」よりも、前進する道のある短く明確な「ノー」を好むことを学びました。
