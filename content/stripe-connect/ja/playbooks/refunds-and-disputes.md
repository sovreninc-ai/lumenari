# 返金と紛争のプレイブック

お金が既に動いた後、事態は複雑になる。判断ツリーは以下のとおり。

## よくある 4 つの状況

### 1. 顧客が全額返金を要求、紛争なし

運営者起点の返金。簡単なケース。

```ts
const refund = await stripe.refunds.create({
  payment_intent: pi.id,
  refund_application_fee: true, // プラットフォームの取り分も返金する
  reverse_transfer: true,        // 接続アカウントからお金を戻す
});
```

`reverse_transfer: true` で接続アカウントの残高が不足している場合、Stripe はデビットを作成し、次のペイアウトサイクルまで接続アカウントはマイナス残高となる。

管理 UI で表示する: 「この返金は [Org] の次回ペイアウトから $X を引き出します。」

### 2. 顧客が部分返金を要求

同じコードに `amount` を加える:

```ts
const refund = await stripe.refunds.create({
  payment_intent: pi.id,
  amount: 5000, // $50（セント）
  refund_application_fee: true,
  reverse_transfer: true,
});
```

Stripe はプラットフォーム手数料を比例的に返金する。元の分割が 50/50（$120 で $60/$60）で顧客に $50 戻す場合、プラットフォーム手数料の返金は $25、接続アカウントの transfer 逆送も $25。

異なる分割（例: プラットフォームが返金全額を負担）を望む場合、`refund_application_fee: false` を設定して手動で逆送する:

```ts
await stripe.refunds.create({ payment_intent: pi.id, amount: 5000 });
// reverse_transfer なし、refund_application_fee なし — プラットフォームが吸収。
```

### 3. 顧客が銀行にチャージバックを申し立てる

これは返金ではなく紛争。ライフサイクルが異なる。

顧客の銀行が Stripe からお金を引き戻す。Stripe はあなたのプラットフォームから引き戻す。`charge.dispute.created` webhook が届く。証拠を提出するのに約 7〜14 日。

```ts
async function handleDispute(d: Stripe.Dispute) {
  // 1. 運営者（あなた）に通知 — 人間の注意が必要。
  await sendDisputeAlert(d);

  // 2. DB で購入を「紛争中」とマーク。
  await db.from("purchases")
    .update({ disputed_at: new Date().toISOString(), dispute_reason: d.reason })
    .eq("stripe_payment_intent", d.payment_intent);

  // 3. 接続アカウントに知らせるべきなら、そちらにも通知。
  await notifyConnectedAccount(d);
}
```

証拠の提出は、最初の数件はダッシュボード経由で行う — Stripe の Web フォームは API よりガイドが手厚い。プロセスができたら `stripe.disputes.update` で自動化する。

紛争に勝てば、お金が戻る。負ければチャージバックは確定し、接続アカウントも自分の取り分を失う可能性がある。

### 4. ペイアウトが既に発生した後の返金

ケース 1 または 2 と同じコード。Stripe が会計を処理する。接続アカウントは Stripe 元帳でマイナス残高になり、次のチャージまで、または銀行振込で補填するまで続く。

運用上、ここがカスタマーサービスで最も失敗しがちな場所。管理 UI に「本当によろしいですか?」のインタースティシャルを作る: 「これは [Org] のアカウントから $X を引き出します。現在の残高は $Y です。次のペイアウトまでマイナス残高ポジションとなります。」

## エッジケース

### 紛争のあった取引、既に半額返金済み

$120 の取引のうち $50 を既に返金しており、顧客が残り $70 を争った場合、Stripe は元のチャージ全額（$120）から返金済み $50 を引いた $70 を範囲とする。証拠パッケージで部分返金に言及すること。

### 紛争中の接続アカウントがプラットフォームを離脱

2 つのケース:

1. **問題ないアカウント、単に離脱:** チャージへの紛争は依然プラットフォームに来る。決着させ、その後でアカウントを閉じる。
2. **不正または規約違反で停止されたアカウント:** Stripe は予想される紛争をカバーするため、90 日間残高を保持する場合がある。接続アカウントはその期間が満了するまで最終ペイアウトを受け取れない。

実際にオフボーディングする前に、接続アカウントとオフボーディングフローを文書化すること。

### 返金時の通貨ミスマッチ

CAD でチャージし接続アカウントが USD ペイアウトを保持している場合、Stripe は変換し FX 手数料を取る。プラットフォームが通常負担する（UX としてきれい）。顧客にぴったり全額を返したい場合、わずかな FX 損失を計算に含めること。

## 管理 UI で表示すべきもの

各取引について:

- 元のチャージ金額と日付
- プラットフォーム手数料、接続アカウントの取り分、Stripe 手数料
- 返金（日付、金額、起案者）
- 紛争（ステータス、証拠提出期限、結果）
- 「これを返金」ボタン、各当事者への金額影響を表示する確認付き

「この取引で何が起きたか」を 30 秒以内に答えられないなら、管理 UI は完成していない。
