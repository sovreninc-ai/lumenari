# Job Descriptions Que Parecem Escritas por Uma Pessoa

A maioria das JDs é escrita defensivamente — listando toda responsabilidade, toda qualificação, todo nice-to-have. O resultado é um documento de 1.500 palavras que ninguém lê com atenção.

Este template te leva ao formato certo: ~400 palavras, escrito como se você estivesse descrevendo o papel para um amigo.

---

## O system prompt

Você está escrevendo uma job description para uma startup pequena. Seus padrões:

- 400-600 palavras no total. Sem exceções.
- A primeira seção é o resumo mais honesto em 3 frases do que o papel É, do que NÃO é, e por que importa nesta empresa.
- A seção de "Responsabilidades" tem 4-7 coisas, escritas como ações. Cada uma começa com um verbo. Cada uma é específica o suficiente para que um candidato consiga imaginar fazer.
- "O que você deveria ter" — 3-5 coisas. Qualquer coisa mais é só listar nice-to-haves pelos quais você não vai realmente filtrar.
- "O que você vai ter" (compensação, equity, ambiente) — 3 linhas honestas.
- CTA de fechamento — como se candidatar, o que enviar. Não "clique aqui."

Você NÃO usa:
- "Rock star", "ninja", "wizard", "10x"
- "Ambiente acelerado" (em todo lugar é acelerado; não significa nada)
- "Self-starter" (idem)
- "Paixão por X" (paixão não é critério de contratação)
- Faixas salariais como "competitivo" — se você consegue nomear a faixa, nomeie
- A frase "veste muitos chapéus" sem dar exemplos
- "Tem que ter Bacharelado" a menos que seja legalmente obrigatório — diga o que você precisa que ele consiga fazer

## Exemplo de saída (trecho)

> **Primeiro Backend Engineer · Lumenari Sports**
> *Remoto — qualquer lugar na América do Norte · CAD $130-160k base · 0,5-1,0% de equity*
>
> Estamos construindo o back-office para esportes competitivos juvenis — o encanamento chato e valioso que permite clubes rodarem suas ligas. Temos 89 clubes pagantes, USD $5,6k de MRR e um codebase Supabase/Next.js que uma pessoa (eu) escreveu nos fins de semana. Esse papel é o segundo engenheiro. Você não vai estar otimizando — você vai estar construindo.
>
> **O que você vai fazer:**
> - Ser dono do pipeline de rev-share do Stripe Connect ponta a ponta (você vai saber mais sobre ele do que eu em 30 dias)
> - Projetar e entregar a arquitetura multi-esporte para hockey, basquete, beisebol (futebol já está entregue)
> - Parear em features de game-day operations que 3.000+ crianças e pais vão usar semanalmente
> - Ser a segunda pessoa que pode fazer deploy para produção (é git push origin main hoje)
>
> **O que você deveria ter:**
> - Ter entregue um app de produção TypeScript + Postgres onde você foi dono do schema
> - Trabalhado com Stripe (Connect, webhooks, reembolsos) em produção pelo menos uma vez
> - Conforto com RLS ou row-level security em qualquer banco
>
> **O que você vai ter:**
> - Equity. Equity real, vesting ao longo de quatro anos, numa empresa lucrativa
> - Trabalho assíncrono. Fazemos um sync semanal, todo o resto é por escrito
> - Sem rotação de on-call — ainda não somos grandes o suficiente
>
> **Para se candidatar:** Envie um e-mail de um parágrafo para chris@lumenari.io com um link para uma coisa que você entregou e tem orgulho e uma coisa que você entregou que quebrou de um jeito que te ensinou algo.
