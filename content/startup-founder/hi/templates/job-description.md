# Job Descriptions जो एक Person के लिखे जैसा पढ़ें

ज़्यादातर JDs defensively written होते हैं — हर responsibility, हर qualification, हर nice-to-have listing। Result एक 1,500-word document है जिसे कोई carefully नहीं पढ़ता।

यह template आपको right shape तक लाता है: ~400 words, ऐसा लिखा जैसे आप एक friend को role describe कर रहे।

---

## System prompt

आप एक small startup के लिए एक job description लिख रहे हैं। आपके defaults:

- 400-600 words total। कोई exceptions नहीं।
- पहली section role क्या IS, क्या NOT है, और यह इस company पर क्यों matters का सबसे honest 3-sentence summary है।
- "Responsibilities" section 4-7 things है, actions के रूप में written। हर एक एक verb से start होता है। हर एक काफी specific है कि candidate इसे करते हुए imagine कर सके।
- "क्या आपके पास होना चाहिए" — 3-5 things। इससे ज़्यादा बस nice-to-haves listing है जिन पर आप actually filter नहीं करेंगे।
- "आपके पास क्या होगा" (compensation, equity, environment) — 3 honest lines।
- Closing CTA — कैसे apply करें, क्या भेजें। "Click here" नहीं।

आप ये use NOT करते:
- "Rock star," "ninja," "wizard," "10x"
- "Fast-paced environment" (हर जगह fast-paced है; इसका कोई मतलब नहीं)
- "Self-starter" (same)
- "Passion for X" (passion एक hiring criterion नहीं है)
- "Competitive" जैसी salary ranges — अगर आप range name कर सकते हैं, name करें
- Examples दिए बिना phrase "wear many hats"
- "Must have a Bachelor's degree" जब तक legally required न हो — कहें आप क्या चाहते हैं वे करने में able हों

## Example output (excerpt)

> **First Backend Engineer · Lumenari Sports**
> *Remote — anywhere in North America · CAD $130-160k base · 0.5-1.0% equity*
>
> हम youth competitive sports के लिए back-office बना रहे हैं — boring, valuable plumbing जो clubs को अपनी leagues चलाने देती है। हमारे पास 89 paying clubs, $5.6k MRR, और एक Supabase/Next.js codebase है जो एक person (मुझे) ने weekends पर लिखा। यह role दूसरा engineer है। आप optimize नहीं करेंगे — आप build करेंगे।
>
> **आप क्या करेंगे:**
> - Stripe Connect rev-share pipeline को end-to-end own (आप 30 days के अंदर मुझसे अधिक इसके बारे में जानेंगे)
> - hockey, basketball, baseball के लिए multi-sport architecture design और ship करें (soccer already shipped है)
> - Game-day operations features पर pair करें जिन्हें 3,000+ kids और parents weekly use करेंगे
> - दूसरे person हों जो production deploy कर सकें (आज `git push origin main` है)
>
> **आपके पास क्या होना चाहिए:**
> - एक production TypeScript + Postgres app shipped जहाँ आपने schema own किया
> - Production में कम से कम एक बार Stripe (Connect, webhooks, refunds) के साथ काम किया
> - किसी भी database में RLS या row-level security के साथ comfort
>
> **आपके पास क्या होगा:**
> - Equity। Real equity, चार साल over vesting, एक profitable company में
> - Async work। हम एक weekly sync करते हैं, बाकी सब लिखित में
> - कोई on-call rotation नहीं — हम अभी इतने बड़े नहीं हैं
>
> **Apply करने को:** chris@lumenari.io को एक one-paragraph email भेजें एक thing जो आपने shipped किया है जिस पर आप proud हैं के link के साथ और एक thing जो आपने shipped किया जो एक तरह से broke जिसने आपको कुछ सिखाया।
