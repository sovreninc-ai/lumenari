# 面接準備 + フォローアップ

> STAR / 行動 / 技術面接の準備、加えてどんな就活にも必要な 3 種のフォローアップメール: サンキュー、リジェクション後、ゴースト回復。

---

## パート 1 — 行動面接準備（STAR）

### STAR が実際にどう機能するか

多くの人が STAR を間違える理由は、回答の 80% を Situation と Task に費やすこと。面接官はセットアップに興味がない。**あなた** が何をしたか、何が起きたかに興味がある。

正しい比率:

- **Situation (10%)**: 1 文。「Acme で、全イベントの約 12% で Webhook リトライ失敗が発生していました。」
- **Task (10%)**: 1 文。「私はその四半期のオンコールエンジニアで、その失敗で週 2 晩起こされていました。」
- **Action (60%)**: **あなた** が取った具体的ステップ。「we」でなく一人称「I」。これが本体。
- **Result (20%)**: 数値があれば数値。結果 — チーム、顧客、ビジネスに対して。

「we」を 2 回以上言うと、面接官はあなたが何をしたか分からない。「I」を使う。本当に協働の仕事なら、「私がリードした」または「2 名のエンジニアが Y を扱う間、私が X 部分を所有した」と言う。

### 準備プロンプト

```
私が STAR フォーマットで行動面接の回答を準備するのを手伝ってください。
質問と話したいおおまかなストーリーを渡します。あなたは約 200 ワードの
引き締まった STAR 回答を生成します。

ルール:
1. Situation: 最大 1 文。
2. Task: 最大 1 文。
3. Action: 回答の 60%。一人称「I」。協働の仕事なら、
   私が具体的に何を所有し、他の人が何をしたかを名指す。
4. Result: 数値または具体的結果で締める。数値がないなら、
   捏造する前に訊く。
5. 約 200 ワード。声に出して 90〜120 秒できれいに読める。
6. バズワード禁止 (passionate、results-driven、dynamic)。詰め物なし。

回答を生成した後、面接官が最も訊きそうなフォローアップ質問を 1 つ
訊いてください。有用なら、それに先回りで対応する短い追記を提案。
```

### 準備しておくべき 6〜8 個のストーリー

どんなオンサイトの前にも、異なる質問に対して柔軟に対応できる 6〜8 個のストーリーを準備。多くの行動質問はこれらのテーマのバリエーション:

1. 何かをリードした時
2. ピアまたはマネージャーと意見が合わなかった時
3. 失敗した時
4. 速く学ぶ必要があった時
5. 難しいトレードオフをした時
6. 誰かをメンタリングまたは育成した時
7. プレッシャーの中で届けた時
8. ステークホルダーに押し返した時

各々について、3〜4 文の文脈 + 結果を書く。スクリプトを暗記しているのではない — 原材料を準備し、AI が瞬時に正しい回答に整形できるようにしている。

### 出力例

**質問:** 「マネージャーと意見が合わなかった時のことを教えて。」

**ユーザーから AI への原入力:**

```
Acme で、私のマネージャーは顧客が待っているからと、フィーチャーフラグなしで
4 週間で新しい決済機能を出荷したがった。それは悪い判断だと思った — 私たちは
フラグなしで決済を出荷したことがなく、顧客はもう 1 週間に気付かないと思った。
押し戻し、最終的にフラグを追加し、2 週間で機能を展開。週 1 でバグを発見、
100% で出荷していたら約 $80k のコストがかかっていた。
```

**AI が生成する STAR 回答:**

```
Acme で、私のマネージャーは主要顧客が待っているため、フィーチャーフラグ
なしで 4 週間で新しい決済機能を出荷するよう推進しました。

私はデプロイを所有しており、反対しました — フラグなしで決済変更を出荷
したことがなく、顧客が追加 1 週間を感じるとも思いませんでした。

runbook を引き出し、リスクを書き出しました: 100% ロールアウト時のバグは
全顧客に当たり、決済での平均的な売上影響インシデントは約 $80k。フィーチャーを
フラグし、2 週間で 5% から 25% から 100% に展開することを提案。マネージャー
はタイムラインの圧力で 2 回押し戻しましたが、アーキテクチャは譲らず、
ロールアウト計画を説明するための顧客コールを自分で取ると申し出ました。
フラグを追加しました。

週 1 の 25% で、フルロールアウトでは重複請求を発生させていた Webhook
リトライバグを発見。回避コスト推定: 約 $80k。ロールアウトをビルドと
並行計画していたため、顧客は元の日付に機能を取得。マネージャーと私は
それ以降、すべての決済デプロイをデフォルトでフラグするようになりました。

(想定フォローアップ:「マネージャーの押し戻しをどう処理したか？」 —
追記する一文: 何を最適化しているか彼に訊き、それを顧客と明示的に
合意した上で、意見でなくデータで意見が分かれるようにアーキテクチャの
論拠を書面で示しました。)
```

220 ワード、約 100 秒で読め、判断、所有、コミュニケーション、結果を示します。フォローアップ提案がボーナス — AI は面接官が掘り下げそうな箇所にフラグを立て、事前に組み立てた応答を提供します。

## パート 2 — 技術面接準備

### AI が得意なこと

- アルゴリズム問題のパターンマッチングとソリューションのかたちの説明。
- 標準ルーブリック（機能要件、非機能、API、データモデル、規模、ボトルネック、トレードオフ）でシステムデザイン問題を歩く。
- デバッグやコードリーディング質問のモック面接。
- 「もし〜だったらどうする」フォローアップ生成、部屋で驚かないように。

### AI が苦手なこと

- 実際の練習の置き換え。コードを書く / ホワイトボードでデザインするのはあなた自身。AI のソリューションを読むのは、プレッシャー下で生み出すのと同じではない。
- **あなたの** 面接官が何を訊くかの予測。AI は平均をシミュレートできる、実際の部屋は独自のもの。

### 有用なプロンプトパターン

**システムデザイン:**

```
明日 <会社> でシステムデザイン面接があります。役職は <senior backend>。
この問題で 45 分をどう構成するか歩いて見せて:
「Stripe ライクなプラットフォーム向けの Webhook 配信システムを設計」。

その後、防衛できるよう準備したいデザイン選択について 3 つ質問してください。
```

**アルゴリズム:**

```
動的計画法が錆びついています。中難度の DP 問題を 3 個、それぞれに 1 行
ヒント付きで出してください。まだ解は見せないで。私が挑戦して戻ります。
```

**モック面接:**

```
あなたはバックエンド役職で私を面接するシニアエンジニア。デバッグ質問を
1 つ訊いてください。私が応答した後、面接官のようにフォローアップを訊く。
助けないで — 押してください。最後に、私の回答がどう着地したか教えてください。
```

「助けないで、押して」の一行が重要。AI は既定で優しくなる。モックで優しさはいらない、実際の面接官が訊く質問が欲しい。

## パート 3 — 3 種のフォローアップメール

### メール 1 — 面接後のサンキュー（24 時間以内に送信）

**プロンプト:**

```
就職面接後の 100〜130 ワードのサンキューメールを書きます。ルール:

1. 面接官が言った具体的な事象に 1 つ言及。汎用「お時間ありがとうございました」
   ではなく。
2. 適合性について 1 つ簡潔に強化 — 会話で最も強かったシグナルを選ぶ。
3. フォローアップ質問のドアを開ける。役職を懇願しない。
4. 締めはプロフェッショナルで、必死でない。
5. 件名:「Thanks — <my name> / <role>」

渡すもの: 面接官の名前、役職、彼らが言った具体的な事象 1 つ、
強化したい事象 1 つ。
```

**出力例:**

```
件名: Thanks — Alex / Senior Backend Engineer

Maya 様

本日はお話できてありがとうございました。Webhook の並び順について、
リトライが順序外れで届いたときにどう考えているかの話が印象に残りました — それは
私がおそらく健全な量を超えて時間を費やしてきた問題で、Acme で私たちが
取ったアプローチと同じ方向で考えていらっしゃるように聞こえました。

チームのお役に立つようでしたら、昨年書き上げた具体的なリトライ順序の
判定ツリーを歩いて喜んで共有します — タイプするより生で共有するほうが
簡単な類のものです。いずれにせよ、お話できてうれしかったです。
ループの残りもスムーズに進むことを願っています。

— Alex
```

メールアドレスを持つすべての面接官に 1 通、人ごとに個別化。具体的言及だけが変わるなら同じメールを単語通り使い回しても OK — ただし具体的言及は **変えなければ** なりません。

### メール 2 — リジェクション後（No の 48 時間以内に送信）

これは重要。多くの人が送らない。送る人々は、何か月後に適切な役職が開いた時、温かい紹介と「ぜひ覚えておきたい」フォローアップを得ます。

**プロンプト:**

```
就職リジェクションへの 80〜100 ワードの優雅な応答を書きます。ルール:

1. 時間と決定への感謝。恨み節なし。
2. 面接を蒸し返さずに結果を承認。
3. ドアを開けたまま: 連絡を保つよう依頼、将来の適切な役職への開放性を伝える。
4. 任意: フィードバックを 1 つ求める。直接的に (「5 分で 1 つの具体的な
   フィードバックがあれば」) — 曖昧な依頼 (「フィードバックいただければ」)
   は曖昧な回答を生む。
```

**出力例:**

```
Maya 様

ご連絡いただきありがとうございました、そしてチームのこのループへの時間にも
感謝します。会話は、この就活で得た中でも良い部類のものでした — 着地点に
ついて正直にお伝えくださり、ありがとうございました。

決済領域のシニアバックエンド役職が年内に開いた場合、リストに入れて
いただければ幸いです。そして、もし 5 分で、何が他方に傾いた具体的
フィードバックを 1 つお伝えいただける時間があれば、参考になります。

よろしくお願いします。
Alex
```

「1 つの具体的なフィードバック」依頼は、このように表現すると約 40% の確率で答えられる。汎用「フィードバック」は 5%。

### メール 3 — ゴースト回復（14 日音沙汰なし）

2 段階。7 日目は軽い ping。14 日目は本物のフォローアップ。

**7 日目（軽い ping）:**

```
Maya 様

[日付] にお話したシニアバックエンド役職について、念のため確認です。
お役に立つ追加情報があれば喜んで。

— Alex
```

以上。3 行。詰め物を追加しない。

**14 日目（本物のフォローアップ）:**

```
件名: Quick follow-up — Senior Backend / Lumenari

Maya 様

[日付] にお話したシニアバックエンド役職についてのフォローアップです。
ループは候補者と無関係な様々な理由で遅くなることを承知していますので、
どちらでもプレッシャーはありません — ただ、役職がまだ開いているか、
私の立ち位置を確認したくご連絡しました。

そちらでタイミングが変わったなら、知らないより知るほうが助かります。
答えが No であってもそれで結構です。就活を計画するためにクロージャー
をいただければありがたいです。

— Alex
```

14 日目のメールから 1 週間以内に返信がなければ、失注扱いで進む。3 通目のフォローアップは送らない。シグナルは十分明確。

## このプレイブックがやらないこと

- スクリプトを暗記する。回答を声に出して練習する。AI は言葉を整形できる、あなたの口がそれらを知っている必要がある。
- オファーを受けるべきか教える。それは価値観の問題。何が重要かのリストを作り、重み付けする。AI はリストを作る手伝いはできるが、判断はできない。
- 給与交渉のカバー。これは別のプレイブックで、ここでの誤ったツールは高くつく。当面は: 電話で受諾しない、24〜48 時間取る、市場データを錨にカウンターを 1 つ。
