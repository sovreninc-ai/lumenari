# 渐进披露 —— 先展示那 20%

原则：第一次接触时，绝不展示 80% 的用户都用不上的内容。

## 表单

14 个字段的表单会吓跑人。三种压缩方式：

### A. 先只放必填

只展示真正必填的字段。下方加一个"更多详情"切换，藏住可选字段。

```
姓名 *
邮箱 *

▸ 更多详情（3 个可选字段）

[ 继续 ]
```

### B. 多步、每屏一段

每个屏幕 2-4 个字段，单列。用户清楚还剩多少（"第 2 步 / 共 4 步"）。

不要把 14 个字段假装"多步"地塞成 7 屏 × 2 字段 —— 那更糟。请按真正的意义分组。

### C. 智能默认

如果 80% 的用户会选同一个值，就预填。在字段帮助文本里说一句。

```
币种：CAD（IP 显示你在加拿大）
```

## 设置

设置页是重灾区。Apple 风格的经典结构：

```
最常用（≤5 项）
─────────────────────
项目 A
项目 B
项目 C

高级
─────────────────────
▸ 账户与隐私（8 项）
▸ 通知（12 项）
▸ 开发者（6 项）
```

按用户心智模型分组，而不是按你的内部数据模型。

## 仪表盘

首屏应当回答一个问题："我的东西现在怎么样？"

其余都属于滚动区。首屏：

```
[ 大数字 —— 主指标 ]
[ 一句话总结 ]
[ 一条 sparkline 或一个可视化 ]
```

下面再放更深入的数据。用户只在想看时才会滚。

## 详情页

首屏只展示要点。把密集细节藏在 Tab 或"点击展开"后面。

例如套件详情页：
- 首屏：名称、slogan、价格、主 CTA
- 下方：包含什么（5 条要点，不是 50 条）
- "你将收到的文件" —— 列表默认折叠，点击展开

## 何时**不要**用渐进披露

- 关键信息（同意条款、价格、退款政策）—— 绝不可隐藏。
- 错误 —— 始终立即可见。
- 破坏性操作上的必备确认 —— 绝不可隐藏。
- 法律要求必须显眼之处。

## 如何挑选要展示的内容

问："如果用户只在这屏停 5 秒，他必须带走的那一件事是什么？"

把它放到首屏、用最大字号、用最强对比。其余都是次要的。
