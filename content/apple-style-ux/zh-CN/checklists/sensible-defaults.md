# 合理默认清单

规则：只在答案真的重要、并且你无法推断时，才问用户。

## 静默应用的默认

| 决策 | 合理默认 |
|---|---|
| 币种 | 用户 IP 推断的国家，附一键切换 |
| 语言 | 浏览器 `Accept-Language` 头，设置中提供切换 |
| 时区 | 浏览器探测，显示但不打断 |
| 日期格式 | 按地区（en-CA → YYYY-MM-DD；en-US → MM/DD/YYYY） |
| 首次引导 | 跳过欢迎轮播；直接落到空状态 |
| 邮件频次 | 交易类 + 每月一次产品动态，附退订 |
| 主题 | 跟随 `prefers-color-scheme: dark` |
| 通知 | 默认关闭，直到用户做某件能从通知中受益的事 |
| 自动保存 | 打开 |
| 破坏性操作的确认 | 打开（弹窗本身就是摩擦） |
| 保存格式 | 与打开时一致（PDF 保持 PDF，.md 保持 .md） |
| 排序 | 最近优先 |
| 分页 | 每页 20 项 |

如果你想往 UI 里加 "要不要…？"，请先问：能不能直接做，并提供撤销？

## 何时该问用户

以下情况要问：

1. **操作具有破坏性且不易撤销。** 删除账户、清除历史。
2. **操作会真花钱。** 预约课程、处理付款。
3. **该选择会显著影响后续行为。** 工作区名称、初始团队。
4. **你真的无法推断。** 名字、岗位、为何使用本产品。

每屏只问一件事。别把五个问题塞进一个表单。

## 怎样问得好

```
[ 一句话问题，同时充当标题 ]

[ 正文 —— 仅当问题需要上下文时才放 ]

[ 选择界面 —— chip group、radio 或文本框 ]

[ 继续按钮 —— 在做出选择前为禁用 ]
```

例子：

> **你的俱乐部教什么项目？**
> 我们会自动配好相应的年龄组、级别与排期默认值。
>
> [ 足球 ] [ 冰球 ] [ 篮球 ] [ 棒球 ] [ 其他 ]
>
> [ 继续 → ]

对比反面版本：

> ☐ 选择主要项目
> ☐ 选择次要项目（可选）
> ☐ 选择管理机构
> ☐ 选择典型赛季长度
> ☐ 选择年龄组（多选）
>
> [ 提交 ]

反面版本一上来就是 5 个问题。好的版本只问一个，其余推断。

## 最难的版本

最难的版本是："当用户意图含糊时，AI 应该怎么做？"

默认：选最合理的解读、把事做了、并告诉用户做了什么。提供切换解读的入口。

```
我默认你说的是 2026 春季赛季（当前激活的那个）。
如果你指的是其他赛季，可以从这里更换。
```

这就是 Apple 的 "你是不是想…？" 的工作方式。不要拦截；提供出路。
