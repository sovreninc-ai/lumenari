# プログレッシブディスクロージャー — まず 20% を見せる

原則: 80% のユーザーが必要としないものを、初接触で見せない。

## フォーム

14 フィールドのフォームは人を遠ざける。圧縮するパターンは 3 つ:

### A. 最初は必須のみ

本当に必須のフィールドのみ表示。下に任意項目用の「詳細」トグル。

```
名前 *
メール *

▸ 詳細（任意 3 項目）

[ 続行 ]
```

### B. 画面ごとに 1 セクションのマルチステップ

各画面は 2〜4 フィールド、1 カラム。ユーザーは残りが何かを正確に見られる（「ステップ 2/4」）。

14 フィールドのフォームを各 2 フィールド × 7 画面に擬似マルチステップ化しない — それはもっと悪い。意味のあるグループにする。

### C. スマートデフォルト

80% のユーザーが同じ値を選ぶなら、事前に入れる。フィールドのヘルパーテキストで触れる。

```
通貨: CAD（IP からカナダと推定）
```

## 設定

設定画面は最大の違反者。標準的な Apple スタイルの構造:

```
よく使う設定（5 項目以下）
─────────────────────
項目 A
項目 B
項目 C

詳細
─────────────────────
▸ アカウントとプライバシー（8 項目）
▸ 通知（12 項目）
▸ 開発者（6 項目）
```

内部データモデルではなく、ユーザーのメンタルモデルでグループ化する。

## ダッシュボード

ダッシュボードはファーストビューで 1 つの問いに答えるべき: 「自分のあれはどうなっている?」

それ以外はスクロール領域。トップ:

```
[ 大きな数字 — プライマリーメトリック ]
[ 1 文の要約 ]
[ 1 つのスパークラインまたはビジュアル ]
```

その下、より深いデータ。ユーザーが望むときにのみスクロールする。

## 詳細ページ

初期ロードでは必須を表示。密な詳細はタブまたはクリックで展開の裏に隠す。

例えばキット詳細ページでは:
- ファーストビュー: 名前、タグライン、価格、プライマリー CTA
- ファーストビュー下: 中身（5 つのブレット、50 ではない）
- 「受け取れるファイル」 — ユーザーがクリックして展開するまでデフォルト折りたたみ

## プログレッシブディスクロージャーを使うべきでないとき

- 重要情報（同意、価格、返金ポリシー） — 決して隠さない。
- エラー — 常にすぐ見える。
- 破壊的アクションへの必須確認 — 決して隠さない。
- 法的に目立たせる必要のあるもの。

## 何を見せるかの選び方

問う: 「ユーザーがこの画面に 5 秒しかいなかったら、持ち帰るべき 1 つのことは何?」

それがファーストビューで、最大の文字、最高のコントラスト。それ以外はすべてセカンダリー。
