# マイクロコピーのパターン

## ボタン

ボタンは結果を説明する、システムアクションではない。動詞で始める。

| 悪い | 良い |
|---|---|
| Submit | 招待を送信 |
| OK | 変更を保存 |
| Process | 今すぐ支払い |
| Confirm | 登録をキャンセル |
| はい | イベントを削除 |

ルール: ボタンコピーを単独で読む。何が起きるか分かるか? 分からなければ書き直す。

破壊的アクションでは、動詞そのものが警告となる: 「アカウントを削除」 — 「本当によろしいですか?」の二重確認ではなく。

## 空状態

空状態は画面に対するユーザーの第一印象。「アイテムが見つかりません」で無駄にしない。

形:

```
[ アイコン — 控えめに、装飾的すぎず ]

コンテンツがあるときの、この画面の目的を説明する見出し
（1 文）

そこに到達する方法を説明する本文の 1 文。

[ そこに導く CTA ]
```

例:

> **ライブラリは今のところ空です。**
> キットを購入すると、必要なすべてのダウンロードがここに保存されます。
> [ キットを見る → ]

> **今週はイベントなし。**
> コーチが練習や試合を予定すると、ここに表示されます。
> [ 今後の予定を見る → ]

## エラー

良いエラーメッセージは 3 つの問いに答える:
1. 何が起きたか?
2. 誰のせいか（システムか自分か）?
3. 今何をするか?

```
下書きを保存できませんでした。
接続が切れました。もう一度試してください — 入力したテキストはまだここにあります。
[ もう一度試す ] [ オフラインコピーを保存 ]
```

避けるべきこと:
- 「問題が発生しました」 — 無意味
- エラーコード単独 — サポート用であり、ユーザー用ではない（見出しではなく詳細に置く）
- 暗黙にユーザーを責める（「入力が無効です」 — 誰の基準で無効?）
- スタックトレース

## オンボーディング

各オンボーディングステップは 1 つの仕事を持つ。仕事を兼ねない。

Apple のオンボーディングパターンは通常:
1. **ウェルカム / バリュープロップ画面** — このアプリが何をするか、1 文
2. **重要な 1 つの権限リクエスト** — それだけ
3. **最初の有用な画面** — チュートリアルではなく、実際のプロダクト

アンチパターン: 全機能を説明する 5 画面のカルーセル。ユーザーはまだそれを読む忍耐を獲得していない。

機能に説明が必要なら、最初に現れたとき「了解」または「OK」で消えるインライン説明として説明する。

## 確認ダイアログ

不可逆または高コストのアクションのために予約。各ダイアログは摩擦の税。

形:

```
何が起きるか（1〜2 文、具体的に）

[ キャンセル ] [ 動詞-アクション ]
```

例:

> **このイベントを削除しますか?**
> 14 件の RSVP とアップロードされたファイルも削除されます。
>
> [ キャンセル ] [ イベントを削除 ]

注意: プライマリーボタンはアクションの動詞、「はい」ではない。キャンセルはセカンダリーで、等しい重みではない。

## ローディング状態

3 つの種類:

1. **200ms 未満** — 何も表示しない。目は気づかない。
2. **200ms〜2s** — 欠けたコンテンツの代わりに控えめなスピナーまたはスケルトン。
3. **2s 超** — 明示的なメッセージ: 「キットのおすすめを生成しています…」 — ユーザーが「自分のために何かが進んでいる」と分かるように。

不確定スピナーは、本当に推定できないときにのみ誠実。推定できるなら、プログレスバーを使う。

## 成功状態

成功したアクションには、自身を祝うモーダルは要らない。トースト、チェックマーク、控えめにスライドインする「保存しました」で十分。

祝祭的な状態は、本物のマイルストーン（初の請求書支払い、100 番目の顧客など）のために予約 — そのときでも簡潔に。
