# 内容更新手册

你能做的最高杠杆 SEO 工作,通常不是写新文章。是修好你已经发过的那些。本手册告诉你何时更新、何时重写、何时合并、何时删除 —— 以及每种操作对应的安全提示词。

---

## 更新决策树

把每篇候选文章按顺序过一遍。命中第一项即停。

### 步骤 1:取数据

对每篇你正在考虑的文章,取:

- 该主关键词的当前 Google 排名(Search Console)
- 过去 12 个月的平均排名走势
- 点击率
- 当前 SERP 前 3 名
- 文章的 `datePublished` 和 `dateModified`
- 指向该 URL 的外链(Ahrefs、Semrush 或你用的工具)

10 分钟的数据采集,能避免你做错更新。

### 步骤 2:跑决策树

**Q1:文章是否排在第 1 页或第 2 页?**
- 是 → **原地更新。** 保留 URL,保留内部链接,保留外链。只更新实质内容。
- 否 → 继续。

**Q2:文章是否排在第 3-5 页,且意图错位?**
(例如,你的文章是教程,但现在 SERP 奖励对比文)
- 是 → **围绕正确意图重写。** 保留 URL。把它当作一篇借用旧 URL 权重的新文章来写。
- 否 → 继续。

**Q3:你是否有两篇文章在抢同一个关键词?**
- 是 → **合并。** 选更强的那个 URL(外链更多、当前排名更好)。把较优的内容合进去。把较弱的 URL 301 到强的。
- 否 → 继续。

**Q4:查询的含义是否发生了根本变化?**
(例如,功能改名;AI Overview 在吃点击;SERP 转向视频)
- 是 → **大改写。** 新角度,如需新格式。仅当旧文章仍有足够相关性 + 外链值得保 URL 时,才保 URL。
- 否 → 继续。

**Q5:话题是否已经过时?**
(例如,产品已不存在;法律已变更;框架已退役)
- 是 → **删除并 301** 到最相近的现有文章。如果没有相近的,返回 410(gone)。
- 否 → 继续。

**Q6:文章在排名,但同比流量下滑?**
- 是 → **原地更新 + 加深度。** 大概率被一篇更新的文章蚕食了。刷新实质内容、补齐缺失、更新 meta。
- 否 → 暂不动,再观察一个季度。

## 模式 1:原地更新(最常见的更新)

适用于排在第 1-2 页、只需要更新一下的文章。

### 你做什么

- 更新过时的统计与事实
- 如果 UI 变了,更换截图
- 如果话题有了新维度,加新子段
- 加强薄弱段落(在 PostHog/Hotjar 等里滚动深度低的那些)
- 如果之后发过更好的相关内容,更新内部链接
- 更新 `dateModified` schema
- **不要**改 URL
- **不要**删掉正在带来排名的段落

### 提示词

```
你是 SEO 内容策略师。

我在原地更新这篇文章。URL 不变。结构大部分不变。

**Article URL:** [URL]
**主关键词:** [keyword]
**当前排名:** [position]
**当前 SERP 前 3:** [粘贴]
**最近发布/修改:** [日期]

**文章当前样子(粘贴):**
[full article]

我想要:
1. diff 风格的修改清单(附理由)
2. 你会新增的段落或现有 H2 下新增的子段
3. 需要更新的过时事实/统计(标 "需要来源")
4. 仅当当前 meta 弱时,给出更新后的 meta 标题和描述
5. 新段落的内部链接建议

**不要**重写已经工作的段落,除非你能明确指出它表现不佳的原因。
```

### 范例输出

> **Diff 方案:**
>
> 1. **更新 H2 #3("Pricing comparison")** —— 表格还是 2024 价。HubSpot、Pipedrive、Salesforce 都涨了。从每家定价页拉当前价。*(需要来源:各厂商当前定价页)*
> 2. **在当前 #4 和 #5 之间新增 H2:"2026 年有什么变化"** —— 讲每家 CRM 现在打包的 AI 功能。这是 SERP 现在给较新文章排名的方向。约 250 字。
> 3. **加强 H2 #5("Best for under 20 contacts")** —— 目前 180 字,加一个真实测试故事可以翻倍。PAA 数据显示用户在搜这个具体切面。
> 4. **更新内部链接** —— 旧版链接 `/crm-pricing-teardown`,该 URL 现已重定向。改到当前 URL `/saas-pricing-deep-dive`。
> 5. **Meta 标题保留**(它在工作,54 字符,主关键词在前)。
> 6. **Meta 描述更新** —— 当前那一版是 H1 改写。替换成:"Tested 7 CRMs for 90 days each — refreshed for 2026 with new AI features, current pricing, and the one I'd actually pick today."(153 字符)
>
> **不要动的段落:**
> - "How I tested these" 是你的 E-E-A-T 脊梁,正在拿排名。留着。
> - H1 保留。它是带来点击的标题。
>
> **缺什么:**
> - 你目前没覆盖 "free CRM for solopreneurs" —— PAA 显示这个切面有真实搜索量。考虑放在 H2 #4 下作为 H3。

## 模式 2:围绕新意图重写

当你的文章排在第 3-5 页,是因为 Google 现在对这个查询想要不同的格式。

### 意图变化的信号

- 当前 Top 3 的格式与你发布时不同
- 即使在 5-7 名,CTR 也低于 1%(说明你出现了但没人点)
- PAA 问题变了
- 出现了 AI Overview

### 你做什么

- 保留 URL(它有权重)
- 按新 SERP 出新提纲
- 新 H1、新 meta 标题、新 meta 描述
- 给链接到旧版的人留一段简短的过渡说明,**或者**保留旧角度的一部分作为子段,让那些外链仍然显得相关

### 提示词

```
你是 SEO 内容策略师。

我要围绕新意图重写这篇文章。URL 不变。

**Article URL:** [URL]
**主关键词:** [keyword]
**当前排名:** [position]
**当前 SERP 前 3:** [粘贴]
**文章当前样子:**
[full text]

我观察到的:
- [我为什么认为意图变了 —— SERP 上有什么改变]

我想要:
1. 新 SERP 的意图分类
2. 新提纲(深度同 article-outliner 模板)
3. 旧文章中(如有)应该原文保留的段落
4. 更新后的 meta 标题 + 描述
5. 关于外链连续性的说明 —— 我会担心丢哪些吗?
```

## 模式 3:合并两篇互相竞争的文章

当你发现你在自己吃自己。

### 如何识别

- Search Console 显示你两个 URL 都在同一个关键词上有展现
- 两个 URL 都徘徊在第 2-3 页,上不去
- 两个都没有明显的内容深度或外链优势

### 你做什么

- 选活下来的 URL(外链更多,或更干净地匹配查询)
- 把弱的 URL 中较好的内容合进活下来的那个
- 把弱的 URL 301 到活的
- 更新所有指向弱的 URL 的内部链接

### 提示词

```
你是 SEO 内容策略师。

我有两篇文章在抢同一个关键词。需要合并。

**关键词:** [primary keyword]

**Article A:**
- URL: [A]
- 当前排名:[position]
- 外链:[count]
- 发布日期:[date]
- [粘贴全文]

**Article B:**
- URL: [B]
- 当前排名:[position]
- 外链:[count]
- 发布日期:[date]
- [粘贴全文]

我想要:
1. 选定活下来的 URL,附理由
2. 一份从两篇里取最好的统一提纲
3. 合并后的完整草稿
4. 当前指向失败 URL 的内部链接清单(需要更新)
5. 301 方案
```

## 模式 4:大改写(查询含义已根本变化)

最难的判断。文章还在排,但世界变了。例子:AI Overview 现在直接回答查询,导致流量掉了 60%;你写过的框架被废弃了;搜索行为从文字转向视频。

### 你做什么

- 大改写,通常完全新角度
- 根据外链价值决定 URL 命运:若有强外链,保留并重写;若没有,新 URL 也行
- 更新 meta、schema、内部链接

这其实不算"更新" —— 是借旧 URL 权重写一篇新文章。当作新文章来写,用 article-outliner 模板(`templates/article-outliner.md`)。

## 模式 5:删除 + 301

当话题确实已经过时。

### 例子

- 你评测过的产品下线了
- 你写过的法律被替换了
- 你教过的框架退役了
- 时效热点已过,你也不打算更新

### 你做什么

- 把 URL 301 到最相近的现有文章
- 如果没有相近的,返回 410(gone),让 Google 干净地移除
- 不要只是删掉等 404 —— 那是浪费外链权重

## SERP 意图分析器提示词

当你拿不准用哪个更新模式时,用这个。

```
你是 SEO 内容策略师。

帮我分类这篇文章需要哪种更新。

**Article URL:** [URL]
**主关键词:** [keyword]
**当前排名:** [position]
**12 个月趋势:** [上升 / 稳定 / 下滑]
**当前 SERP 前 3:** [粘贴]

**文章(粘贴):**
[full article]

跑我的更新决策树。告诉我:
1. 适用哪种模式(原地更新 / 意图重写 / 合并 / 大改写 / 删除)
2. 理由
3. 我该走的第一个具体步骤
```

输出应该是一个清楚的"模式 X,因为 Y"答案,加上第一步。如果 AI 含糊或说"看情况",推它一下:"如果非选一个,你选哪个?"

## 范例 —— "what is HubSpot used for"

一次真实的更新决策。文章排第 4。CTR 0.8%。当前 Top 3 被简短的定义型答案统治,AI Overview 引用了其中两个。文章目前 1,800 字,开头是营销话术。

**决策树跑一遍:**
- 第 1 页?差一点(#4)。第 2 页地带。
- 意图错位?是的 —— SERP 要短、定义性、事实先行的内容。文章是长文,带营销腔。
- 两篇互相竞争?否。
- 查询根本变了?有点 —— AI Overview 的出现压缩了点击价值。
- 话题过时?否,HubSpot 还在。

**裁决:** 模式 2(围绕新意图重写)。保留 URL(它有 12 条外链)。改成事实先行的定义型,顶部 50 字答案,然后展开。去掉营销腔。直接对准精选摘要。

**预期结果:** 排名从 #4 升到 #1-2,但绝对点击数未必跳很大,因为 AI Overview 还是在吃点击。胜利在于 AI 引用中的品牌出现,以及在品牌相关变体查询上的自然恢复。

## 工具包会标记的常见更新错误

- **更改一篇排在第 1 页的文章的 URL。** 你会丢排名和外链权重。原地更新。
- **删除文章而不 301。** 浪费外链,Search Console 里出现 404。
- **不查清流量为什么掉就更新。** 有时文章没问题,**查询本身**搜索量掉了。先看 Search Console 总展现,再断定是文章的问题。
- **更新过于频繁。** 多数文章 6-12 个月一次是合适节奏。每月更新对 Google 来说很可疑,也烧你时间。
- **改 `dateModified` 但不更新实质。** Google 会发现,把新鲜度信号打折。
- **删掉正在带来排名的段落。** 在动刀前一定看滚动深度和段落停留数据。

## 更新节奏 —— 如何规划一年

一个小内容团队每月可以高效更新 4-8 篇。一个人操作建议每月 2-3 篇,按以下优先:

1. 过去 90 天绝对流量掉得最多的文章
2. 排在 4-15 名、CTR 潜力高的文章
3. 被你高流量页面链接到的文章(更新这些有内部链接复利)
4. 18+ 个月未碰过的文章

对每篇跑更新决策树。选模式。执行。不要全部更新和重发;有些会告诉你删除或合并。那就是手册在起作用。
