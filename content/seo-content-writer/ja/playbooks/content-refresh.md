# コンテンツリフレッシュ・プレイブック

SEO で最もレバレッジが効く仕事は、新規記事を書くことではなく、すでに持っている記事を直すことです。このプレイブックは、いつ更新するか、いつ書き直すか、いつ統合するか、いつ削除するかを示し、それぞれを安全に実行するプロンプトも提供します。

---

## リフレッシュ判定ツリー

各候補記事をこのツリーに順番にかけてください。最初にマッチした時点で止めます。

### ステップ 1: データを引き出す

検討対象の各記事について、次を取得します:

- 主要キーワードの現在の Google 順位（Search Console）
- 過去 12 か月の平均順位トレンド
- クリックスルー率
- 現在の SERP 上位 3 件
- 記事の `datePublished` と `dateModified`
- その URL を指すバックリンク（Ahrefs、Semrush、その他使用ツール）

10 分のデータ収集が、間違ったリフレッシュを防ぎます。

### ステップ 2: ツリーを実行

**Q1: 記事は 1 ページ目または 2 ページ目でランクしているか？**
- YES → **その場で更新。** URL を保持、内部リンクを保持、バックリンクを保持。実質だけを更新する。
- NO → 続行。

**Q2: 記事は 3〜5 ページ目でランクし、インテントが不一致か？**
（例: あなたの記事はチュートリアルだが、SERP は今や比較記事を報酬している）
- YES → **正しいインテントを軸に書き直す。** URL を保持。古い URL の権威を使う新記事として扱う。
- NO → 続行。

**Q3: 同じキーワードで競合する 2 記事があるか？**
- YES → **統合する。** より強い URL（バックリンクが多い、現在の順位が良い）を選ぶ。より良いコンテンツをそちらにマージ。弱い方を強い方に 301。
- NO → 続行。

**Q4: クエリの本質が変わったか？**
（例: 機能名が変わった、AI Overview がクリックを食う、SERP が動画にシフト）
- YES → **大幅な書き直し。** 新しい角度、必要なら新しいフォーマット。古い記事に URL 保持を正当化できる十分な関連性 + バックリンクがあるときのみ URL を保持。
- NO → 続行。

**Q5: トピックは廃れたか？**
（例: 商品がもう存在しない、法律が変わった、フレームワークが引退した）
- YES → **削除して 301** を最も近い現行記事へ。近いものが何もなければ 410（gone）を返す。
- NO → 続行。

**Q6: 記事はランクしているが、前年比でトラフィックを失っているか？**
- YES → **その場で更新 + 深みを追加。** おそらく新しい記事にクリックを奪われている。実質をリフレッシュし、欠けているものを追加し、メタを更新。
- NO → 放置し、もう四半期モニタリング。

## パターン 1: その場で更新（最も一般的なリフレッシュ）

1〜2 ページ目でランクしており、軽い更新だけが必要な記事向け。

### やること

- 古くなった統計と事実を更新
- UI が変わったらスクリーンショットを差し替え
- トピックに新しい次元があれば、新しいサブセクションを追加
- 弱いセクション（PostHog/Hotjar 等でスクロール深度が低いもの）を強化
- それ以降より良い関連コンテンツを公開したら内部リンクを更新
- `dateModified` スキーマを更新
- URL を **変えない**
- 順位を稼いでいるセクションを **削除しない**

### プロンプト

```
あなたは SEO コンテンツストラテジストです。

私はこの記事をその場でリフレッシュしています。URL は据え置き。構造の大半は据え置き。

**記事 URL:** [URL]
**主要キーワード:** [キーワード]
**現在の順位:** [順位]
**現在の SERP 上位 3 件:** [貼る]
**最終公開 / 更新:** [日付]

**現状の記事 (貼る):**
[全文]

求めるもの:
1. 変更内容の diff スタイルリスト (理由付き)
2. 追加すべき新セクション、または既存 H2 内のサブセクション
3. 更新が必要な古い事実 / 統計 (「出典が必要」フラグ付き)
4. 現在のメタが弱い場合のみ、新メタタイトル + ディスクリプション
5. 新セクション向けの内部リンク提案

動いているセクションは、低パフォーマンスの具体的理由を名指せない限り書き直さない。
```

### 出力例（ワークサンプル）

> **差分プラン:**
>
> 1. **H2 #3「料金比較」を更新** — 表は 2024 年の価格。HubSpot、Pipedrive、Salesforce すべて変動済み。各ベンダーの価格ページから現行価格を引いてください。*(出典が必要: 各ベンダーの現行価格ページ)*
> 2. **現在の #4 と #5 の間に新 H2「2026 年に何が変わったか」を追加** — 各 CRM が今バンドルする AI 機能に触れる。SERP が今、新しい記事をランクさせている軸。約 250 ワード。
> 3. **H2 #5「20 連絡先以下に最適」を強化** — 現在 180 ワード、実テストの逸話で倍にできる。PAA データはユーザーがこの具体的な切り口を検索していることを示す。
> 4. **内部リンクを更新** — 旧版は `/crm-pricing-teardown` にリンクしているが、現在はリダイレクト。現行 URL `/saas-pricing-deep-dive` に更新。
> 5. **メタタイトルは据え置き**（動いている、54 文字、主要キーワード前置）。
> 6. **メタディスクリプション更新** — 現在は H1 の言い換え。これに置換: 「Tested 7 CRMs for 90 days each — refreshed for 2026 with new AI features, current pricing, and the one I'd actually pick today.」(153 文字)
>
> **触ってはいけないセクション:**
> - 「How I tested these」セクションは E-E-A-T の背骨で、順位を稼いでいる。残す。
> - H1 は据え置き。クリックを稼いでいるタイトル。
>
> **欠けているもの:**
> - 現在「free CRM for solopreneurs」に触れていない — PAA データはこの切り口に実ボリュームがあることを示す。H2 #4 の中に H3 として追加を検討。

## パターン 2: 新しいインテントを軸に書き直す

このクエリに対して Google が今、別のフォーマットを欲しているために 3〜5 ページ目でランクしている記事向け。

### インテントが変わったシグナル

- 今日の上位 3 件のフォーマットが、公開当時と異なる
- 順位 5〜7 でも CTR が 1% 未満（表示はされているがクリックされていない）
- PAA の質問が変わった
- AI Overview が現れた

### やること

- URL を保持（権威がある）
- 新 SERP に合致する新アウトライン
- 新 H1、新メタタイトル、新メタディスクリプション
- 旧版にリンクした人向けの簡潔なリダイレクト・コンテキスト注記を追加するか、元の角度をサブセクションとして十分に保ち、それらのバックリンクが関連性を保つようにする

### プロンプト

```
あなたは SEO コンテンツストラテジストです。

私はこの記事を新インテントを軸に書き直しています。URL は据え置き。

**記事 URL:** [URL]
**主要キーワード:** [キーワード]
**現在の順位:** [順位]
**現在の SERP 上位 3 件:** [貼る]
**現状の記事:**
[全文]

観察したこと:
- [インテントがシフトしたと思う理由 — SERP で何が変わったか]

求めるもの:
1. 新 SERP のインテント分類
2. 新しいアウトライン（記事アウトライナーテンプレートと同等の深さ）
3. 旧記事のうち、原文のまま保つべきセクション（あれば）
4. 更新されたメタタイトル + ディスクリプション
5. バックリンク継続性の注記 — 失うことを心配すべきか？
```

## パターン 3: 競合する 2 記事を統合する

自分自身をカニバライズしていると発覚したとき。

### 見分け方

- Search Console で 2 つの URL が同じキーワードでインプレッションを稼いでいる
- どちらの URL も 2〜3 ページ目をうろつき、上昇しない
- コンテンツの深さやバックリンクで明確な優位がない

### やること

- 生き残る URL を選ぶ（バックリンクが多い、またはクエリにより明確にマッチ）
- 負ける URL のより良いコンテンツを生き残りにマージ
- 負ける URL を生き残りに 301
- 負ける URL を指すすべての内部リンクを更新

### プロンプト

```
あなたは SEO コンテンツストラテジストです。

同じキーワードで競合する記事が 2 つあります。統合が必要です。

**キーワード:** [主要キーワード]

**記事 A:**
- URL: [A]
- 現在の順位: [順位]
- バックリンク: [数]
- 公開: [日付]
- [全文を貼る]

**記事 B:**
- URL: [B]
- 現在の順位: [順位]
- バックリンク: [数]
- 公開: [日付]
- [全文を貼る]

求めるもの:
1. 生き残る URL を理由付きで選定
2. 両方からベストを抽出した統合アウトライン
3. 完全マージ済みドラフト
4. 負ける URL を現在指す内部リンクのうち、更新が必要なもののリスト
5. 301 プラン
```

## パターン 4: 大幅な書き直し（クエリの本質が変わった）

最も難しい判断。記事はまだランクしているが、世界が動いた。例: AI Overview が今クエリに答えるためトラフィックが 60% 減、書いたフレームワークが廃止、検索行動がテキストから動画にシフト。

### やること

- 大幅な書き直し、しばしば角度ごと刷新
- バックリンク価値に基づいて URL の運命を決める: URL に強いバックリンクがあれば保持して書き直す、なければ新 URL でもよい
- メタ、スキーマ、内部リンクを更新

これは厳密には「リフレッシュ」ではなく、旧 URL の権威を使った新記事です。新規記事を書くのと同じく扱い、記事アウトライナーテンプレート（`templates/article-outliner.md`）を使ってください。

## パターン 5: 削除して 301

トピックが本当に廃れたとき。

### 例

- レビューした商品がシャットダウン
- 書いた法律が置き換わった
- 教えたフレームワークが引退
- 旬を過ぎたトレンド記事で、更新する気がない

### やること

- URL を最も近い現行記事に 301
- 近いものが何もなければ 410（gone）を返し、Google にきれいに削除させる
- 単に削除して 404 のまま放置しない — バックリンク資産の無駄

## SERP インテント分析プロンプト

どのリフレッシュパターンが当てはまるか判断できないときに使います。

```
あなたは SEO コンテンツストラテジストです。

この記事に必要なリフレッシュ種別を分類するのを手伝ってください。

**記事 URL:** [URL]
**主要キーワード:** [キーワード]
**現在の順位:** [順位]
**12 か月トレンド:** [改善 / 安定 / 低下]
**今日の SERP 上位 3 件:** [貼る]

**記事 (貼る):**
[全文]

私のリフレッシュ判定ツリーを実行してください。教えて:
1. どのパターンが合うか (その場で更新 / インテント書き直し / 統合 / 大幅書き直し / 削除)
2. 理由
3. 私が取るべき最初の具体的ステップ
```

出力は「Y の理由でパターン X」という明確な回答 + 最初のステップであるべき。AI がぼかしたり「場合による」と言ったら押す:「1 つ選ぶならどれ？」

## 出力例 —「what is HubSpot used for」

実際のリフレッシュ判断。記事は #4 でランク。CTR は 0.8%。SERP 上位 3 件は今や、AI Overview が 2 件を引用した短く定義スタイルの回答が支配。記事は現在 1,800 ワードで、マーケティングピッチで始まる。

**判定ツリー実行:**
- 1 ページ目？ ほぼ（#4）。2 ページ目領域。
- インテント不一致？ はい — SERP は短く、定義型、事実先行のコンテンツを求めている。記事はロングフォームでマーケ寄り。
- 競合する 2 記事？ なし。
- クエリ本質変化？ ほぼ Yes — AI Overview の存在がクリック価値を圧縮。
- トピック廃止？ なし、HubSpot は今もしっかり存在。

**評決:** パターン 2（新インテントを軸に書き直し）。URL を保持（バックリンク 12 本）。事実先行の定義型として再構成、冒頭に引き締まった 50 ワード回答、その後展開。マーケピッチ調を捨てる。強調スニペットを直接狙う。

**期待される結果:** 順位が #4 から #1〜2 へ上昇するが、AI Overview がそもそもクリックを食うため絶対クリック数は劇的には跳ねないかもしれない。勝ち取るのは AI 引用におけるブランドプレゼンスと、ブランド派生クエリでのオーガニック回復。

## キットがフラグするよくあるリフレッシュミス

- **1 ページ目でランクしている記事の URL を変える。** 順位とバックリンク資産を失う。その場でリフレッシュ。
- **301 せずに記事を削除する。** バックリンクの無駄、Search Console の 404 エラー。
- **トラフィック低下の理由を確認せずリフレッシュ。** 記事は正常で、**クエリ** のボリュームが落ちただけのこともある。記事が問題と決めつける前に Search Console の総インプレッションを確認。
- **リフレッシュが頻繁すぎる。** 大半の記事は 6〜12 か月ごとが適切なケイデンス。月次リフレッシュは Google から見て怪しく、時間を浪費する。
- **実質を更新せずに `dateModified` だけ更新。** Google はこれを検知し、鮮度シグナルを割り引く。
- **順位を稼いでいるセクションを削除する。** 削る前に必ずスクロール深度とセクション滞在時間データを見る。

## リフレッシュケイデンス — 1 年をどう計画するか

小規模コンテンツチームは月に 4〜8 記事を生産的にリフレッシュできます。ソロ運営者は月 2〜3 記事を目標に、次の優先順位で:

1. 過去 90 日で最も絶対トラフィックを失った記事
2. CTR ポテンシャル高めで順位 4〜15 の記事
3. 高トラフィックページからリンクされた記事（これをリフレッシュすると内部リンク効果が複利化）
4. 18 か月以上手付かずの記事

それぞれにリフレッシュ判定ツリーを実行。パターンを選ぶ。実行。全部をリフレッシュして再公開しない。中には「削除」「統合」と告げるものもある。それがプレイブックが機能している証拠です。
