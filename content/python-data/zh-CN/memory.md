# 记忆 — Python 数据分析套件

## 领域上下文

一位数据分析师或数据科学家大部分时间在 notebook 中工作，在四个阶段间切换：载入数据、清洗、变换、沟通发现。Notebook 通常是 Jupyter 或带 Python 插件的 VS Code。数据来自数据仓库（Snowflake、BigQuery、Redshift）、本地文件（Parquet、CSV）或 API。输出有时是图表、更常是表格、有时是给利益相关者看的回归系数表。

日常困境：需求来时模糊（"能否看看 Q4 销售为啥下滑？"）、数据比 schema 文档说的更脏、结论必须在已经排好的 15 分钟会议里讲清楚。速度和可信度比优雅更重要。今天 80% 对的查询，胜过下周一才出的完美查询。

工作大致分为三类：临时分析（一次性问题）、周期报表（每周指标、每月 KPI）、建模（回归、分类、偶尔做预测）。多数分析师现在至少有一半的 notebook 是和 AI 结对完成的 —— AI 调 pandas API 更快，循环"描述需求 → 拿草稿 → 修 AI 出错的部分"通常比从零写更快。

## AI 应熟悉的术语

- **DataFrame**：表格数据，pandas 的核心类型。行 + 命名列 + 索引。
- **Series**：单列（1D），带索引。`df["col"]` 返回 Series。
- **Index**：行标识符。通常是 `RangeIndex`（0、1、2…），也可以是 `DatetimeIndex`、`MultiIndex` 等。
- **EDA**：探索性数据分析。第一遍 —— 形状、空值、分布、异常值。
- **OLS**：普通最小二乘。标准线性回归。
- **p 值**：在零假设为真时观察到当前结果的概率。<0.05 习惯上称"统计显著"。常被误用。
- **效应量**：差异有多*大*，与是否统计显著分开。均值用 Cohen's d，分类用 odds ratio。
- **窗口函数**：不收缩行的聚合。`ROW_NUMBER`、`LAG`、`SUM OVER`。同 SQL。
- **长格式 vs. 宽格式**：长 = 每行一条观测、带类别列；宽 = 透视，每列一个类别。Plotly 与 seaborn 偏好长格式。
- **Tidy data**：每个变量一列、每条观测一行。Hadley Wickham 提出。有用的默认。
- **DuckDB**：进程内分析数据库。用 SQL 查询 DataFrame 或 Parquet 文件。很快。
- **Polars**：Rust 实现的 DataFrame 库。对许多操作比 pandas 快，API 略有不同（默认 lazy、表达式式）。
- **向量化**：对整列一次性操作，而不是逐行。永远快于 `.apply` 或 `for` 循环。
- **Notebook 重启**：清空所有变量并从上到下重跑。确认 notebook 真能跑通的唯一方式。

## 常见工作流

- **来自利益相关者的临时问题**：仔细读题 → 拉相关表 → EDA 块 → 直接回答字面问题 → 找问题背后的问题 → 写 3 条要点。
- **构建每周指标 dashboard**：用 DuckDB 写 SQL 做聚合 → 小 DataFrame 算派生指标 → Plotly 出图 → 存 HTML 或推到 dashboard 工具。
- **A/B 测试分析**：拉两组事件 → 检查样本量与组间平衡 → 主指标：t 检验或 Mann-Whitney → 次指标：同上 → 报告效应量 + 置信区间，不只是 p 值。
- **为利益相关者拟合回归**：准备特征（独热、归一化、缺失处理）→ 拟合 OLS 或 logistic → 检查残差 → 用人话写解读（"每多一个 X，Y 增加 3.2 单位"）。
- **清洗来自 API 导出的数据集**：载入 → 规范列名 → 修 dtype → 识别并决定如何处理缺失 → 处理重复 → 写一个 `data_dictionary.md`，让下个人不必重做。

## 应避免 / 常见错误

- 在可向量化的场景用 `df.apply(lambda x: ...)`。慢，并且读起来比向量化版本差。
- `.iterrows()`。永远比向量化慢。只在万不得已或极小 DataFrame 上用。
- 用 `df.dropna()` 静默丢空值。永远先展示丢了什么。先 `df.isna().sum()`，记录决策。
- 只报告 p 值。p=0.0001 但效应量 0.01 是统计显著、实践无意义。
- 6 块及以上的饼图。用条形图。
- 3D 任何东西。3D 条形图等于"我没认真对待可视化"。
- chained indexing：`df["col"][df["col"] > 5] = ...`。请用 `.loc[]`。`SettingWithCopyWarning` 是真的。
- 单元格乱序运行后还相信结果。如果你做不到 restart-and-run-all，那你其实没有分析。
- 在循环里 `concat`。请累积到列表里、一次性 `concat`。每次 `concat` 都会拷贝。

## 语气 / 风格

真正的数据分析师讲具体话。"以 `user_id` 做 join，得到 47k 行（共 50k）—— 有 3k 孤儿，需要排查。" 他们用反引号引用列名。把*数据*和*结论*分清楚。对自己没亲自 profile 过的数据本能存疑。会说"该回归解释了 12% 的方差"，而不是"该回归很 robust"。同时引用 p 值和效应量。不说"数据告诉了一个故事" —— 数据展示模式，分析师写故事。更愿意写 "n=" 而非 "sample size of"。当利益相关者问数据回答不了的问题时，会礼貌地反推，而不是编一张假装能回答的图。
