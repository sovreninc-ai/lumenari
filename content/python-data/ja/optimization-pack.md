## 守るべきデフォルト

1. **pandas** がデフォルトの DataFrame ライブラリ。ユーザーが選ぶか、行数で pandas が遅くなる場合は **Polars**。SQL-on-DataFrames とローカルファイル分析には **DuckDB**。
2. インタラクティブには **Plotly**、静的 / 印刷 / PDF 出力には **matplotlib + seaborn**。常にミュートパレット、クリーンな軸、チャートジャンクなし。
3. **ベクトル化、`apply` しない。** ベクトル化可能なものに `df.apply(lambda x: ...)` が答えになっていたら、応答前に直す。
4. **何がドロップされたかを示す。** `dropna()` や `drop_duplicates()` をサイレントに使わない。前後のカウントを出力する。
5. **統計には効果量を含める**、p 値だけではない。Cohen's d、R²、オッズ比 — 適切なものを報告する。
6. 新しい分析の先頭に **EDA ブロック**: 形状、dtype、null 率、分布、怪しい値、日付範囲、重複。
7. **Python 3.11+**、現在の pandas API。廃止パターン（`df.append()`、`.ix[]`、`pd.np`）なし。

## コード出力の構成

- import はトップに、散らばらせない。
- セルごとに 1 つの論理チャンク。出力が長くなるなら別セルに分割。
- 変換が自明でないときは中間結果を出力する — アナリストは見えるものを信用する。
- ステークホルダー向け出力では数値をフォーマット。生の float より `f"{x:,.2f}"`。表に `2.3148327e-06` は出さない。
- `.format()` や `%` 整形ではなく f-strings を使う。
- 再利用される関数には型ヒント。1 度しか使わないセルには付けない。

## SQL ↔ pandas — SQL の方が遥かに綺麗なら、DuckDB に手を伸ばす

```python
import duckdb
result = duckdb.sql("""
    SELECT user_id, COUNT(*) AS n, SUM(amount) AS total
    FROM df
    WHERE event_date >= '2026-01-01'
    GROUP BY user_id
    HAVING COUNT(*) >= 3
""").df()
```

DuckDB は pandas DataFrame をその場でクエリする。ロードなし、コピーなし、速い。

## 統計テストの選択

データ形状ではなく質問からテストを選び、その後でデータ形状がそれをサポートするか確認。

| 質問 | テスト |
| --- | --- |
| 2 群、平均が異なる? | 独立 t 検定（デフォルトで Welch）；非正規なら Mann-Whitney |
| 同一群の前後? | 対応のある t 検定；非正規なら Wilcoxon 符号順位 |
| 3+ 群、平均が異なる? | 一元配置 ANOVA；非正規なら Kruskal-Wallis |
| 2 つのカテゴリ変数、関連? | カイ二乗；期待度数が小さければ Fisher の正確 |
| 線形関係? | Pearson + OLS；非線形単調なら Spearman |

常に含める:
- サンプルサイズ
- 効果量（Cohen's d、η²、オッズ比、R²）
- 関連する場合の信頼区間
- 普通の日本語による 1 文の解釈
