# アウトリーチと面接

3 つのパート: シニア度と職種ファミリー別のアウトリーチテンプレート、面接質問バンク（スクリーニング + 行動 + 技術）、そして評判を守る温かくも明確なリジェクションメールのコピー。

---

## パート 1 — シニア度別アウトリーチ

ジュニアはスタッフエンジニアとは異なるシグナルに反応します。多くのリクルーターがする間違いは、全員に同じテンプレートを送ること。

### 共通ルール

- 冒頭は最大 3 行。シニア層は 4 秒で DM を閉じる。
- **なぜあなた具体的に** から始める。実在の理由を名指せないなら、理由は存在しない。
- 給与帯を含める。隠すと「うちは低賃金」と叫んでいるようなもの。
- 明確な依頼を 1 つ。「来週 15 分」は「ぜひつながりたい」より勝つ。
- 「I came across your profile and was impressed」禁止。

### Entry / Junior アウトリーチ

トーン: 励まし、明確、成長重視。資格があるか不安を抱えていることが多い。

```
件名: [Company] のジュニアエンジニア役職 — 検討してみませんか？

[Name] さん、

[Company] でジュニアエンジニアを採用しています — 私たちは [1 行プロダクト] を作っています。あなたの [具体的なもの] のプロジェクトを拝見し、[具体的な詳細] の書き方は、チームで求めている明瞭さの水準そのものでした。

役職は USD $90-110K ベース + エクイティ、米国 / カナダ完全リモート。シニアエンジニア 2 名からのメンタリング、最初の 6 か月の大半はペアリング。

話す気があれば、こちらがカレンダーです: [リンク]。なければお気になさらず — 出荷していること自体が素晴らしい。

— [あなた]
```

機能する理由: プロジェクトの具体性、給与帯を明示、メンタリングシグナル、圧をかけない軽い締め。

### Mid アウトリーチ

トーン: プロフェッショナル、役割固有、報酬正直。本当のステップアップか横移動かを知りたがる。

```
件名: [Company] のミッドフロントエンドエンジニア、$130-150K + エクイティ

[Name] さん、

[Company] のミッドフロントエンドエンジニア役職についてご連絡です。現在 [current employer] で [具体的なプロダクト / チーム] を 2 年。私が採用する役職は同様のスコープで、見る価値のある違いが 2 つあります: [違い 1、違い 2 — チーム規模、技術、所有領域など]。

USD $130-150K ベース + 0.02-0.05% エクイティ、完全リモート。[市] にいるならハイブリッド週 2 回も可。

来週 15 分どうですか？ カレンダー: [リンク]。

— [あなた]
```

機能する理由: 在籍企業と期間を名指す、「見る価値のある 2 つの違い」が具体性を生む、帯を明示。

### Senior アウトリーチ

トーン: 対等な仲間として。今月 100 件のリクルーターメッセージを見ている。101 件目にならない。

```
件名: シニアバックエンド役職、$180-220K、[具体的問題] に取り組む

[Name] さん、

[Company] でシニアバックエンドエンジニアを採用しています。仕事は [具体的な問題ステートメント — チームが実際に作っているもの] で、あなたの [ブログ記事 / 講演 / OSS 貢献] の書き方は、私が見つけた中で最も正しいメンタルモデルに近いものでした。

USD $180-220K ベース + 0.05-0.15% エクイティ。米国 / カナダのリモート優先。チームは [人数 + 1 行の説明]。

開いていれば来週 15 分: [カレンダー]。そうでなくても、[具体的な技術的事柄] についてどう思うかは気になります — 求人抜きで話すのも歓迎です。

— [あなた]
```

機能する理由: 求人抜きで話す提案。シニアエンジニアは、彼らをパイプラインではなくピアとして扱うリクルーターを尊重する。

### Staff / Principal アウトリーチ

トーン: 戦略的、問題重視、上限について正直。能動的に転職活動していることは稀。冒頭が本当に仕事をしないといけない。

```
件名: [Company] のスタッフエンジニア役職 — ご意見を伺いたい

[Name] さん、

[Company] のエンジニアリングリーダーシップと共にスタッフエンジニア役職を進めています。**あなたに** 書く理由: [具体的な技術問題 — 例: 「同規模でのモノリスからサービスへの移行」「協調編集向けリアルタイム同期レイヤー」] を実際にやり抜いており、それがまさにここで取り組む問題だからです。

役職の報酬は USD $280-340K ベース + 意味のあるエクイティ (0.3-0.7%)。リモート優先。CTO 直属、35 名チームの中で 3 名のスタッフエンジニアの 1 人。

問題領域に興味があれば、30 分いただきたいです。そうでなければ — JD をお送りして、ネットワークで誰かおすすめがあるか伺ってもよいでしょうか？ カレンダー: [リンク]。

— [あなた]
```

機能する理由: 技術問題を名指す。実在のレンジで報酬を名指す。優雅な逃げ道（面接ではなく紹介）を提供。

## パート 2 — 職種ファミリー別アウトリーチ

### エンジニアリング / テクニカル

上記参照。エンジニア候補者は次に反応する:
- 技術的な具体性（問題、スタック、規模）
- エンジニアリングカルチャーのシグナル（レビュープロセス、デプロイ頻度、オンコール期待）
- 正直な給与帯
- 簡潔でピア調のメッセージ

次で始めない:「exciting opportunity」「passionate team」、資金調達ラウンド、投資家名。

### デザイン (プロダクト / ブランド)

デザイナーは誰と一緒に働くか、どのように意思決定がなされるかを知りたい。デザインが装飾扱いの「fast-paced startups」で痛い目を見てきた。

```
件名: [Company] のシニアプロダクトデザイナー — デザインが意思決定の席に

[Name] さん、

[Company] でシニアプロダクトデザイナーを採用しています。あなたの [具体的プロジェクト] の作品を拝見しました — [具体的判断] の捌き方は、私たちが必要としている思考のかたちです。

気になりそうな点:
- デザインはエンジニアリングではなく CEO 直属
- プロダクトデザイナー 2 名 + デザインリサーチャー 1 名がすでにチームに
- 実在のリサーチ予算、2 週間ごとにユーザビリティテスト
- USD $170-200K ベース + エクイティ、米国 / カナダリモート

20 分の会話に開いていれば、カレンダーはこちら: [リンク]。

— [あなた]
```

機能する理由: デザインが後付けでないことを示すシグナル。チーム構成を名指す。実リサーチ予算を明示。

### セールス (AE、SDR、セールスリーダー)

セールス候補者は報酬プラン、テリトリー、売るプロダクトを知りたい。

```
件名: [Company] のシニア AE — [vertical] 向け、$250K+ OTE

[Name] さん、

[Company] でシニア AE を採用しています。[product] を [vertical/buyer] に販売、商談規模 USD $30-150K ACV。あなたは [current company] で [time]、[similar/adjacent] を販売 — 私が採用するテリトリーは未割り当てかつ上限なし。

報酬: USD $130K ベース + $130K 変動、50/50 分割、達成超過アクセラレータ。クォータは過去 18 か月の AE 達成データに基づき年間 $1.1M。

来週 15 分どうですか？ カレンダー: [リンク]。

— [あなた]
```

機能する理由: 報酬構造が透明。クォータと達成コンテクスト併記。テリトリーと ICP を名指す。

### オペレーション / G&A (財務、人事、法務)

ops 候補者は **実際に何を所有するか** を知りたい。サポートなしの「全部ゼロから作って」で痛い目を見てきた。

```
件名: [Company] の People Ops マネージャー — 実際に所有するもの

[Name] さん、

[Company] で People Ops マネージャーを採用、60 名規模のシリーズ B SaaS。役職は本当に「実在するが不完全な出発点から People 機能を構築する」 — HRIS (Rippling)、基本ポリシー、構築価値のあるカルチャーはありますが、まだ専任 People 担当はいません。

[current company] で 200 名規模に拡大する前にシステムを入れた 4 年が、まさにこの役職が必要とする筋肉です。

USD $140-170K ベース + エクイティ、リモート + 四半期の対面リーダーシップオフサイト。

20 分の会話に開いていますか？ [カレンダー]

— [あなた]
```

機能する理由: 出発点について正直。彼らの経験を実際のニーズにマッピング。

## パート 3 — 面接キット

### スクリーニング (15〜20 分、リクルーター主導)

目標: ベースライン適合の確認、関心度の測定、給与期待のチェック。スクリーンを 20 分超えにしない。

| 質問 | 良い回答の姿 | 赤信号 |
|---|---|---|
| 現在の役割を 3 文で説明してください。 | 簡潔、タイトルでなく **スコープ** を名指す。 | 散漫、防衛的、前職への責任転嫁。 |
| この役職を見ようと思った具体的な理由は？ | JD またはチームに紐づく実在の理由。 | 「何にでも開いてます」「ただ見ているだけ」。 |
| 報酬の希望は？ | 直接的な数字またはレンジ、駆け引きなし。 | 「市場価格で」/ 回答拒否。 |
| 現実的にいつ開始できますか？ | 通告期間を勘案した明確な回答。 | 曖昧（「数か月」）。 |
| これが **合わない** 理由はありますか？ | 懸念について正直、訊くほど関与している。 | 「ありません！」 — 通常は JD を読んでいない。 |

### 行動 (45〜60 分、採用マネージャー + ピア)

STAR 対応: 状況、課題、行動、結果。具体性を聞く。状況ではなく **行動** で深掘り。

#### 共通行動質問

```
Q: スコープやゴールが途中で変わったプロジェクトについて教えてください。何をしましたか？

良い回答の姿:
- 具体的なプロジェクトを名指す、実数値 / 日付
- 変化のトリガーを記述（データ、ステークホルダー、市場）
- 結論だけでなく意思決定プロセスを説明
- 間違えたこと、やり直したことを認める

赤信号:
- 汎用、具体性なし
- 変える側を完全に責める（自己反省なし）
- 「すべて順調でした」 — プロジェクトは順調にいかない、これは sign
```

```
Q: ピアまたはマネージャーと意見が合わなかった時の話。どう解決しましたか？

良い回答の姿:
- 「意見が違った」ではなく実在の対立
- 直接関わった（迂回せず）
- 結果は成熟: 解決または建設的に「意見が異なる」で合意

赤信号:
- 「マネージャーには常に同意します」
- 「言われた通りにやりました」
- 怨念のトーン — まだ怒っている
```

```
Q: 自分のスコープから大きく外れたものを引き受けた時のことを教えて。

良い回答の姿:
- 実在の結果を伴う具体的事例
- 許可またはアライメントを求めた（英雄行為でなく）
- その後自分のレーンに戻った（「今やその領域も自分が運営」ではない）

赤信号:
- 「いつも追加の仕事を引き受けています」
- 英雄譚 — 会社が火事で彼一人が救った
```

#### エンジニアリング固有の行動質問

```
Q: 所有した本番インシデントについて教えて。何が起き、何をし、その後何を変えましたか？

良い回答の姿:
- 具体的なインシデント、説明に技術的深さ
- IR プロセスを記述 (ページ受領、トリアージ、修正、根本原因)
- ポストモーテムでの変更 — 再発防止のために出荷したもの

赤信号:
- 「インシデントに遭ったことがない」(あります。オンコールでなかったか通知されなかった — どちらもシニアには良くないサイン)
- インフラ / 他チームに全責任転嫁
- ポストモーテム学習なし
```

#### セールス固有の行動質問

```
Q: 勝てたはずなのに落とした商談について教えて。何を見落としましたか？

良い回答の姿:
- 具体的な商談、具体的な理由
- 異なる行動を取れた点を名指す
- プロスペクトのせいにしない

赤信号:
- 「勝てたはずの商談を落としたことはない」
- 落とした商談だけマーケ / プロダクトのせいに
- 喪失と向き合うことを拒否
```

#### デザイン固有の行動質問

```
Q: 守ったデザイン判断と、ロールバックしたデザイン判断について教えて。

良い回答の姿:
- どちらも実在の証跡 (リサーチ、データ、顧客インタビュー)
- 「正しかったので押し通した」と「間違ったので方向転換」を区別
- どちらの結果にも快適

赤信号:
- 守った判断しか名指せない (「決して間違わない」)
- 判断がデータインフォームドでなく好み基準に感じる
```

### 技術 / 役割固有 (60〜90 分)

#### シニアフルスタックエンジニア (サンプル)

プローブ領域 (合計 45〜60 分):

1. **コードレビュー** — 200 行の PR（実物、匿名化）を共有、声に出してレビューしてもらう。聴くべき点: 何を捕まえる、何を見落とす、懸念をどう伝える。
2. **システムデザイン** — 「アプリ内の任意オブジェクトに任意ラベルをタグ付けし横断検索できる機能を設計」。聴くべき点: スキーマ設計、インデックス思考、キャッシュ、規模トレードオフ。
3. **デバッグ** — 実在の障害を提示（「午前 2 時のデプロイ後、ユーザーが X を報告。ログ / メトリクスはこれ。どう調査するか歩いて見せて」）。聴くべき点: 仮説生成、最初に何を確認するか、優先順位の付け方。
4. **プロジェクトスコープ** — 「アプリに SSO を追加。PM が 1 段落を渡した。スコープの考え方を歩いて見せて」。聴くべき点: 訊く質問、フェージングの考え方、表面化させるリスク。

決して使わない: 2 時間超の課題、シニアエンジニアへの LeetCode、ブレインティーザー、「なぜマンホールの蓋は丸いのか」。

#### シニアアカウントエグゼクティブ (サンプル)

1. **プロダクトピッチ** — 2 ページのプロダクトブリーフと 15 分の準備時間を与え、こちら（バイヤーペルソナ）にピッチしてもらう。聴くべき点: 発見 vs ピッチの比、反論の捌き方。
2. **相互クロージングプラン** — 商談シナリオを見せ、どう相互クロージングプランを作るか尋ねる。聴くべき点: ステークホルダーマッピング、商談テンポ、リスクの表面化。
3. **パイプライン算数** — 「クォータが $X、平均商談 $Y なら、四半期をどう計画する？」 聴くべき点: 算数リテラシー、コンバージョン率の意識、活動からパイプラインへの思考。

#### シニアプロダクトデザイナー (サンプル)

1. **ポートフォリオウォークスルー** — 30 分。プロジェクトを 1 つ選ぶ。聴くべき点: 意思決定プロセス、リサーチ統合、何を変えるか。
2. **ライブクリティーク** — 実在の Figma ファイルを見せ、批評してもらう。聴くべき点: ヒエラルキー思考、アクセシビリティ意識、フィードバックの伝え方。
3. **ホワイトボード演習** — 「[このアプリ] のオンボーディングを設計。30 分」。聴くべき点: 訊く質問、スケッチ、各選択の理由。

## パート 4 — リファレンスチェック質問

最大 5 つ。尋問でなくキャリブレーション。

```
1. あなたと [候補者] はどのように、どのくらいの期間一緒に働きましたか？

2. [候補者] は何をするために雇われ、その役割は時間と共にどう変わりましたか？（スコープと成長を明らかにする。）

3. 一緒に働いた中で最大の貢献について教えてください。なぜそれは機能しましたか？（具体性を聞く — 曖昧な回答はソフトシグナル。）

4. [候補者] が [target team description] のようなチームに加わる場合、最初の 6 か月で最もサポートが必要なのはどこですか？

5. もう一度雇いますか？ はいなら、同じ役割、よりシニアな役割、別の役割？
```

**訊かないもの:**

- 「何か知っておくべき問題はありましたか？」（バイアスを招き、曖昧な回答）
- 「人柄をどう表現しますか？」（低シグナル、高バイアス）
- 「勤勉な人ですか？」（はい、と言うに決まっている。）
- 保護カテゴリーを探る質問全般

## パート 5 — リジェクションメール

進んだ段階に基づく 3 層。

### Tier 1 — 履歴書のみ、面接なし

```
件名: Re: [役職名] 応募について

[Name] 様

[Company] の [役職] へのご応募ありがとうございます。今ラウンドを精査し、本求人の具体的なニーズにより近いご経歴の他候補者と進めることになりました。

将来の役職にも引き続きご応募いただければ幸いです — 継続的に採用しており、ご経歴は当該機能全般に適合しています。関連する役職が見つかりましたらご連絡します。

ご応募にお時間をいただきありがとうございました。

— [あなた]
```

### Tier 2 — 面接 1 回、進まず

```
件名: [役職] 面接プロセスのご連絡

[Name] 様

先週はお時間ありがとうございました。お待たせするより直接ご連絡したく。

次ラウンドへ進めない結論になりました。会話で具体的に出てきたのは [1 つの具体的な理由 — 例: 「私たちが必要とする経験スケール (B2B、$50M+ ARR) は、直近 2 つの役職が提供できた機会よりも深い」]。これまでのご活動への否定ではなく、本役職への適合の話です。

肯定的に目立った点: [会話の具体的な事象に紐づく誠実な賛辞]。[Company] でご経歴により合う別の役職が開いたら、こちらからまたご連絡したいのですが、よろしいでしょうか？

お時間ありがとうございました。

— [あなた]
```

機能する理由: 会話に紐づく **1 つの** 具体的理由。誠実なポジティブノート。許可付きでドアを開けたまま。

### Tier 3 — 最終ラウンド、オファーなし

```
件名: 最終ラウンドの件でのフォローアップ

[Name] 様

まず、このプロセスに費やしてくださった時間に感謝します。4 回の会話は本物の時間で、真剣に受け止めてくださったことが分かっています。

別の候補者にオファーを出すことに決めました。非回答ではなく、理由について率直にお伝えしたいです:

決め手は [誠実な理由 — 通常は本役職で最も重要な特定次元での他候補者の相対的強さ]。きわどい判断で、パネルフィードバックの中には [あなたへの誠実な肯定的事柄] を具体的に挙げる声もありました。

お役に立つようでしたら、喜んで:
```

### リジェクションで決して書かないこと

- 「異なる方向に進むことに決めました」（非回答。）
- 「合わないようです」（曖昧。）
- 「役職を一時停止しました」（嘘。発覚する。）
- 「ご経歴をファイルに保管します」（誰もファイルに何も保管しない。）
- 「今後のご活躍をお祈り申し上げます」（フォームレター感。）
